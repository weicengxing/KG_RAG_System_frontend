分析实现
一、 总体架构设计 (System Architecture)
我们将系统分为三层：前端展示层、后端服务层、数据与算法层。
1. 技术选型 (Tech Stack)
前端 (Frontend) - 负责“极强的展示性”
框架: Vue 3 (搭配 Vite) 或 React。Vue 上手快，适合毕设。
UI组件库: Element Plus (构建常规界面) + Tailwind CSS (美化布局)。
图谱可视化 (核心): AntV G6 或 Vis.js。
理由：这两个库专门用于画关系图，支持拖拽、缩放、节点高亮，比ECharts更适合做知识图谱。
聊天界面: 仿照 ChatGPT 的 UI 设计。
后端 (Backend) - 负责“稳健的API”
框架: FastAPI (Python)。
理由：比Django轻量，比Flask快，天生支持异步（这对AI接口调用很重要），自动生成API文档（Swagger），答辩时可以直接展示接口文档。
数据与算法层 (Data & AI) - 负责“核心功能”
图数据库: Neo4j。
理由：行业标准，有社区版（免费），查询语言Cypher简单易学，可视化兼容性好。
向量数据库: ChromaDB 或 FAISS。
理由：轻量级，用于RAG中的语义检索。
大模型 (LLM): 调用 DeepSeek (深度求索)、ChatGLM (智谱) 或 OpenAI 的 API。
理由：为了满足“90秒”和“90%准确率”，直接调API比自己在笔记本上跑本地模型快得多，效果也更好。
编排框架: LangChain。
理由：胶水层，把文档解析、LLM调用、数据库读写串起来。
二、 核心功能实现流程 (Implementation Workflow)
模块 1：动态图谱构建流水线 (The Construction Pipeline)
这是你演示的第一个高潮点。
文档上传与解析:
用户上传PDF -> 后端使用 PyPDF2 或 LangChain 的 PDFLoader 读取文本。
可视化: 前端显示一个进度条步骤条 (Steps Component)。
文本分块 (Chunking):
使用 RecursiveCharacterTextSplitter 将长文切成 500-1000 字的块。
可视化: 前端左侧显示原始文本，右侧显示切分后的“块”列表。
实体与关系抽取 (NER & RE) - 关键一步:
技术: 不要训练BERT模型（太慢且难）。设计一个精妙的 Prompt (提示词)，发给 LLM (如 DeepSeek-V3)。
Prompt示例:
"你是一个知识图谱专家。请从以下文本中提取实体和关系，输出为JSON格式：[{'head': '实体1', 'type': '类型', 'tail': '实体2', 'relation': '关系'}]..."
可视化: 后端流式返回结果，前端实时在一个列表中“蹦”出提取到的三元组（张三 -[任职]-> 阿里），营造“实时计算”的感觉。
图谱入库与渲染:
后端解析JSON，生成 Cypher 语句 (MERGE (n:Person {name:'张三'})...) 写入 Neo4j。
可视化: 调用 AntV G6，读取 Neo4j 数据，渲染出力导向图（Force Graph）。
模块 2：沉浸式RAG问答与溯源 (The "White-Box" RAG)
这是你演示的第二个高潮点，也是体现“解释性”的核心。
用户提问: 前端发送问题。
混合检索 (Hybrid Retrieval):
向量检索: 将问题变成向量，在 ChromaDB 中找相似的文本块（找原文）。
图检索: 提取问题中的实体（如“张三”），在 Neo4j 中查找该节点及其 2 跳内的邻居节点（找结构化知识）。
构建上下文 (Context):
将“检索到的原文” + “检索到的三元组” 拼在一起，喂给 LLM 生成答案。
答案生成与解释 (The Explainability):
技术难点: 如何做“溯源”？
后端在返回答案的同时，必须返回被检索到的节点ID列表。
前端展示:
左侧: 聊天框显示文本答案。
右侧 (解释面板):
引用片段: 显示检索到的原文段落。
局部图谱: 这是重点！ AntV G6 画布自动清空，只加载并高亮显示刚才检索到的那些节点ID。这就实现了“答案涉及到哪部分图谱，就亮哪部分”。
三、 针对技术指标的优化策略
如何实现“≤ 90秒”构建图谱？
并发处理: Python 使用 asyncio 或 ThreadPoolExecutor。切分出 10 个文本块后，同时向 LLM 发送 10 个请求进行提取，而不是一个一个等。
流式传输: 前端不要等所有结果都好了再显示，而是后端处理完一个块，就通过 WebSocket 或 SSE (Server-Sent Events) 推送给前端显示。这样用户感觉“系统一直在动”，心理等待时间变短。
如何实现“≤ 10秒”问答？
预加载: 图谱查询在 Neo4j 中非常快（毫秒级）。主要耗时在 LLM 生成。
打字机效果: 答案使用流式输出（Stream），像 ChatGPT 一样一个字一个字蹦出来，首字响应通常在 2 秒内，用户体验极佳。
如何保证“准确率”？
Prompt Engineering (提示词工程): 这是准确率的关键。多调试 Prompt，要求 LLM 严格按照 JSON 格式输出，并对模糊的实体进行消歧。
数据清洗: 在写入数据库前，后端写一段简单的代码过滤掉空数据或格式错误的数据。
